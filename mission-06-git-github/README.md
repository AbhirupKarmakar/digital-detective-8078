# Mission 6 — Git and GitHub


### Task 6.1 — Basic Git workflow

| Git operation | What it does |
|---|---|
| git status | Shows which files have changed and whether they are staged. |
| git add mission-06-git-github/README.md | Selects this README change for the next commit. |
| git commit -m "Document basic Git workflow" | Saves the staged change in the repository's history. |
| git log -5 --oneline | Shows the five most recent commits in a short format. |

Staging selects changes for a commit. Committing saves the selected changes in Git history.

### Task 6.4 — Git command glossary

| Git operation | Meaning |
|---|---|
| git init | Starts a new Git repository. |
| git status | Shows which files have changed. |
| git add | Selects files for the next commit. |
| git commit | Saves selected changes in Git history. |
| git log | Shows earlier commits. |
| git branch | Shows branches or creates a branch. |
| git switch | Changes to another branch. |
| git push | Sends commits to GitHub. |
| git pull | Gets the latest changes from GitHub. |

## 4. Commands / tools used

- git status — checked changed files.
- git add — selected a file for the commit.
- git commit — saved changes in Git history.
- git log — viewed recent commits.
- git switch — changed branches.
- git push — sent the branch to GitHub.
- git pull — got the latest changes from GitHub.
- GitHub — created and reviewed the Pull Request.

## 5. My understanding

Staging selects changes for a commit. A commit saves those changes in Git history. A branch is a separate place to work on changes. A Pull Request lets people review changes before they go into the main branch.
